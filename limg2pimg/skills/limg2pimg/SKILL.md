# limg2pimg —— 长图按页切分

把「手机滚动截屏导出的 PDF 长图」还原成一页一张的图片。

## 快速开始

```bash
# 单张：自动切分 + 页码校验 + 残影去重
python "$SKILL_DIR/split_pages.py" "长图.jpg"

# 整个目录：按文件名自然排序（CBETS2 < CBETS10），每张长图一个子目录
python "$SKILL_DIR/split_pages.py" "D:\某目录"

# 指定输出根目录
python "$SKILL_DIR/split_pages.py" "D:\某目录" --out-dir "D:\输出"

# 不装 OCR 也能用，纯几何切分
python "$SKILL_DIR/split_pages.py" "长图.jpg" --ocr off
```

Windows 下建议用 dsbot_env 的解释器：

```powershell
& "C:\Users\admin\miniconda3\envs\dsbot_env\python.exe" "$SKILL_DIR\split_pages.py" "D:\某目录"
```

## 输出

输出目录里**只有图片**，不写任何 JSON。

**单张**：

```
<图片名>_p01.jpg  …  <图片名>_pNN.jpg     # 按阅读顺序命名的单页图
```

**目录**：

```
某目录/
  CBETS24_pages/
    p01.jpg  …  p22.jpg
  CBETS41_pages/
    p01.jpg  …  p14.jpg
```

子目录内的文件名统一是 `p01.jpg … pNN.jpg`：**零填充保证字典序与阅读顺序一致**
（`p02 < p10`），直接按文件名排序就是正确页序。

重跑同一张长图时，输出目录里上一轮残留的 `p*.jpg` 会先被清掉，避免页数变少后
旧文件混进结果。

目录模式下高宽比 < `--min-aspect`（默认 2.0）的普通图片会被跳过，读不出来或
处理失败的会被记录到日志，**单张失败不会中断整批**。

需要逐页的 y 区间、文档页码、切分依据时，加 `--manifest`，会额外生成
`<图片名>_pages.json`（单张）和 `limg2pimg_index.json`（目录汇总）。

`--manifest` 生成的清单字段：

| 字段 | 说明 |
|------|------|
| `page` | 阅读顺序号 |
| `y0` / `y1` | 在原长图中的像素区间 |
| `height_out` | 输出图片的实际高度（去重后） |
| `page_num` | OCR 读到的文档页码；`null` 表示没读出来 |
| `page_num_inferred` | 由已识别页码反推的页码（文档页码不从 1 起算时用） |
| `footer_text` | 页脚 OCR 原文，便于人工核对 |
| `dedupe_ranges` | 被移除的拼接残影区间 |
| `mode` | `header` = 靠页眉模板切分；`fallback` = 靠空白缝兜底 |

文件名**始终按阅读顺序编号**。文档自身页码可能从正文才开始计（前面有封面、修订记录），
直接拿页码命名会和顺序号撞名，所以页码只写进清单。

## 参数

```
--out-dir DIR     输出目录（默认 <图片目录>/<图片名>_pages）
--ocr auto|on|off 页码识别，默认 auto（装了 rapidocr 就开）
--min-gap N       页面间最小空白高度，默认 120px
--thr N           灰度阈值，默认 170；浅色水印多时调低
--format jpg|png  输出格式，默认 jpg
--quality N       JPG 质量，默认 92
--pad N           每页上下额外保留的像素
--manifest        额外输出 JSON 清单（默认关闭，输出目录只留图片）
--no-dedupe       关闭拼接残影去重
--quiet           只输出结果
```

## 切分原理

只用"空白够大就切"是不行的。实测同一张图里，页间缝只有 270–330px，
而末页内部的表格后留白有 961px —— 纯空白阈值会把一页切成两页。所以分了三级判据：

### 1. 行投影找空白缝（快，全图一次）

`(gray < thr).sum(axis=1)` 得到每行墨迹量，连续空白 ≥ `min-gap` 的就是候选缝。
等价于把长图横切成几万条 1px 窄图逐条判断，但不产生任何文件，几十毫秒跑完。

### 2. 缝后的窄带聚类找页眉（准，决定页数）

每页顶部那行重复标题（本例高 23px、宽 812px）是同一段文字。
对"缝之后第一个内容带"取列墨迹剖面，按内容边界裁齐后重采样成 256 维向量，
余弦相似度 ≥ 0.90 就用并查集聚成一组；成员 ≥ 3、高度和宽度接近的那组就是页眉。

> **必须按内容边界裁齐**：手机拼接截屏时整页会左右抖动上百像素。
> 按绝对坐标取剖面，同一行页眉的相似度会掉到 0.55，聚类直接散掉。

页眉命中数 = 页数，每个页眉前面那条缝的中点就是分页线。

### 3. 页码 OCR 校验（慢，只做确认）

14 页逐页 OCR 要 30 秒。做法是把每页页脚（高度 8–40px 的小字行）裁成一条，
**放大 2 倍后纵向拼成一张大图，一次 OCR** —— 4~6 秒识别全部页脚。
页码与顺序号做偏移拟合，能识别出的页码都等于"顺序号 + 偏移"，就判定切分正确。

## 拼接残影去重

手机滚动截屏在每段停留处会把内容重复拼一次。判据：
同一页内连续 ≥ 3 个内容带与前面一一对应、间距一致、且总高度 ≥ 4% 页高。

只匹配 1~2 个带的不算 —— 正文里重复的表格行、流程图里同款箭头方框太常见，
早先版本用"span ≥ 2"就把一张流程图误删了 31px。

## 已知限制

- 页面**没有页眉**的文档会走 `fallback`：按空白缝 + 页高一致性切，
  遇到页内大留白可能多切，此时页脚页码校验会显示页码不连续，建议人工确认。
- 顶部 App 状态栏/标题栏靠"顶部 5% 内是否有 ≥3 段文本 + 顶部 2% 是否有内容"判断，
  某些截图（标题栏与状态栏连成一段）可能漏判，首页会保留状态栏。
- OCR 依赖 `rapidocr_onnxruntime`；没装时自动跳过，几何切分照常工作。
